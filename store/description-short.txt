Record what you do on a page. Get a Robot Framework suite that runs.

Recorders are not new. What they emit usually is not worth keeping: nth-child
selectors that break when someone adds a div, and Sleep 2 everywhere because the
recorder had no idea what it was waiting for. Zelector is an attempt at the two
things that decide whether a recorded test survives.

WAITS

You cannot record a wait — nobody performs one — so Zelector infers it. It
watches what the page did after each action: which request fired and how long it
took, what appeared, what appeared and then vanished. A spinner that comes and
goes becomes Wait Until Element Is Not Visible on it. A route change becomes
Wait Until Location Contains. Timeouts come from the time the page actually took.
Every guess shows its reason and can be edited before you export.

LOCATORS

Every candidate is scored and every point lost has a reason. Classes generated by
a build tool, ids regenerated on every render, and classes that name a state
rather than an element are recognised and marked rather than handed over as
though they were stable. When nothing durable exists, the panel says so while you
can still go and ask for a data-testid.

THE AWKWARD PART

Closed shadow roots, iframes, alerts, drag and drop, hover menus, rich text
editors, a page that pins a bar to the edge of the window. Each of those is a
recording that quietly replays as nothing at all, and each is handled — because
the suite was run against the live site until it passed, not read until it
looked right.

PRIVACY

One permission: storage, for the recording in progress. No servers, no account,
no analytics, no network requests of any kind. MIT licensed and the source is
public, so every word here can be checked against the code.

NOT YET

The path of an uploaded file cannot be recorded — the browser does not tell
anyone — so the name goes in a variable and you drop the file beside the suite.
Cross-origin iframes give a frame selector that is a guess, and it says so.
